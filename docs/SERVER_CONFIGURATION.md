# Where the configuration lives

A map of **every place where IberoReservations is configured**: the repository, the server
`reservadeii`, Dokploy, Traefik, the Dev Tunnel, Cloudflare and the external accounts. Use it
to answer "where do I change X?" and "what would we lose if the server disappeared?".

Related documents: [DEPLOYMENT](DEPLOYMENT.md) (architecture and history), [RUNBOOK](RUNBOOK.md)
(procedures), [ACCESS](ACCESS.md) (who owns each account and how credentials are handled), the
[server administrator manual](manual/README.md) (Spanish, with diagrams) and the [ADRs](adr/README.md).

> **Verification status.** The server was inspected live on **2026-10-06 (UTC)** with the read-only
> script [`scripts/server-audit/collect.sh`](../scripts/server-audit/README.md) plus a few read-only
> commands, as the unprivileged account `acardena` (privileged parts through `sudo`). Each row says
> what is **Verified** (seen on 2026-10-06), **Repo** (checked in this repository), **Recorded**
> (from the 2026-09-21 inspection in [DEPLOYMENT](DEPLOYMENT.md), not re-checked) or **Not checked**.
> Nothing here contains secret values, only locations and names.

## 1. Short answer

| What | Where it lives | In Git? |
| ---- | -------------- | ------- |
| Application code, SQL, Dockerfiles, Nginx template | GitHub `FernandoJM01/ibero_room_booking`, branch `main` | **Yes** |
| Environment variables and secrets of the API and DB services | **Dokploy** (application, *Environment* tab), stored in the Swarm service specification | **No** |
| Dokploy's own settings (applications, domains, deployment history) | Dokploy's PostgreSQL service `dokploy-postgres`, volume `dokploy-postgres` | **No** |
| Dokploy's own secrets | Docker secrets read as files (`BETTER_AUTH_SECRET_FILE`, `POSTGRES_PASSWORD_FILE`) | **No** |
| Traefik routing | `/etc/dokploy/traefik/` on the server (generated by Dokploy's *Domains* tab) | **No** |
| Database contents | Docker volume `iberoreservations-iberoreservationsdb-oi5kek-data` | **No** |
| Public tunnel service | `/etc/systemd/system/devtunnel-reservations.service` and the tunnel registered at Microsoft | **No** |
| Tunnel login (token cache) | `/home/acardena/DevTunnels/devtunnels-tokens*` on the server | **No** |
| Public proxy (Worker), DNS and the `deii-salas.uk` domain | **Cloudflare** account | **No** (only a copy of the Worker in [DEPLOYMENT §5](DEPLOYMENT.md#5-internet-exposure)) |
| Email (SMTP) mailbox | University IT; credentials in the Dokploy API variables | **No** |
| Firewall and SSH policy | `ufw` and `/etc/ssh/sshd_config*` on the server | **No** |

Everything marked "No" must be rebuilt by hand if the server or an account is lost; see
[section 4](#4-if-the-server-or-an-account-is-lost).

## 2. Request path and who configures each hop

```text
Browser ─HTTPS─► Cloudflare (DNS + Worker "plain-glitter-53dd", domain deii-salas.uk)
                      │  Worker rewrites the URL and sets Host = tunnel host
                      ▼
          Microsoft Dev Tunnel relay  (tunnel ibero-reservas.usw3, owned by one Microsoft account)
                      │  outbound connection opened by the server
                      ▼
 reservadeii ─ systemd unit devtunnel-reservations ─► Traefik :80  (/etc/dokploy/traefik/*)
                                                         ├─ any path ─► web (Nginx)     ┐ Docker Swarm services,
                                                         └─ /api     ─► API (Node.js) ──► PostgreSQL 18  ┘ created in Dokploy
```

## 4. If the server or an account is lost

| Lost | What you need to recreate | Where the information is |
| ---- | ------------------------- | ------------------------ |
| Application code | Nothing: clone GitHub | Repository |
| Dokploy settings (applications, domains, variables) | Re-create the three applications, their domains and every variable | **Variable names**: section 3.2. **Values**: the password manager. **Domains**: [section 5](#5-routes-currently-defined). If `dokploy-postgres` was not backed up, this is rebuilt from documentation |
| Traefik files | Regenerate by re-adding the domains in Dokploy | [section 5](#5-routes-currently-defined) |
| Database | Restore the latest dump into a new PostgreSQL service | **Only exists if someone downloaded one** (today: a 26 KB dump from 2026-09-24). [RUNBOOK](RUNBOOK.md#restore-a-backup) |
| Tunnel unit or login | Recreate the systemd unit and log in again with a Microsoft account | [RUNBOOK](RUNBOOK.md#change-the-account-that-owns-the-dev-tunnel) |
| Cloudflare Worker | Paste the script back and attach the custom domain | [DEPLOYMENT §5](DEPLOYMENT.md#5-internet-exposure) (the only copy) |
| Domain or Cloudflare account | Recover through the registrar or Cloudflare | **Not documented** |

## 6. Verify it yourself (read-only)

Everything in this document was obtained with commands that change nothing. Run
[`scripts/server-audit/collect.sh`](../scripts/server-audit/README.md) as described in its README to regenerate
the full report, or use the individual checks:

| # | Check | Command | Expect |
| - | ----- | ------- | ------ |
| 1 | Services | `sudo docker service ls` | web, API, DB, `dokploy`, `dokploy-postgres`, all `1/1` |
| 2 | Dokploy and Traefik files | `ls -la /etc/dokploy /etc/dokploy/traefik/dynamic` | as in section 3.2 |
| 3 | Routes | `grep -n 'Host(' /etc/dokploy/traefik/dynamic/*.yml` | section 5 |
| 4 | Variable **names** of the API | `sudo docker service inspect iberoreservations-reservationsapi-6ulakn --format '{{range .Spec.TaskTemplate.ContainerSpec.Env}}{{println .}}{{end}}' \| cut -d= -f1` | the names in section 3.2 |
| 5 | Where each volume lives | `sudo docker service inspect <service> --format '{{json .Spec.TaskTemplate.ContainerSpec.Mounts}}'` | section 3.2 |
| 6 | Tunnel unit | `systemctl cat devtunnel-reservations` | `User=acardena`, `Restart=always` |
| 7 | **Tunnel really connected** | `/home/acardena/bin/devtunnel show ibero-reservas.usw3` (as `acardena`) | **`Host connections : 1`** (0 means the site is down) |
| 8 | Deployed commit | `git -c safe.directory='*' -C /etc/dokploy/applications/<service>/code log -1 --oneline` | the latest merged commit |
| 9 | End to end | `curl -s https://deii-salas.uk/api/health` | `{"ok":true,…}` |

Outside the server, someone with the right login should also confirm and write into [ACCESS](ACCESS.md):
the Cloudflare Worker script and DNS records and the account's members; the domain registrar, owner and
renewal date; and that every variable name above exists in Dokploy with its value also in the password manager.

## 7. Gaps worth closing

1. **Monitor the tunnel and restart it automatically.** It was down for ~4 days (2026-10-02 to 2026-10-06) and
   for ~29 h on 2026-09-29 without anyone noticing; see [RUNBOOK](RUNBOOK.md#tunnel-process-running-but-site-down).
2. **Copy the nightly backups off the server** (database) and back up Dokploy's own database. The nightly dump exists since 2026-10-06 but stays on the same disk.
3. **Record the registrar and renewal date** of `deii-salas.uk` and give a second person access to Cloudflare,
   the Microsoft tunnel account and Dokploy ([ACCESS](ACCESS.md)).
4. **Keep the Worker script in the repository** (for example `infra/cloudflare-worker.js`).
5. **Harden SSH and the firewall**: install keys, disable password login and root login, close port 3000 to the network.
6. **Rotate Docker logs** (`/etc/docker/daemon.json`) so they cannot fill the 29 GB disk.
7. **Decouple the web image from the Dokploy service name** by setting `BACKEND_URL` in Dokploy.
8. Remove the retired routes and `reservas.local`; set a real ACME email; delete the unused `render.yaml`.
9. Install pending updates and reboot in a maintenance window (check the tunnel afterwards).
10. Record who owns the second administrator account `admlocal`.
